# Карточка модели: риск-скор One Director

Версия карточки 0.1 (Фаза 0 — шаблон с решениями; числовые метрики появятся после обучения). Владелец разделов 4–7 — агент 05-model; разделы 1–3 и 8–10 меняют только люди.

## 1. Назначение

- **Что делает:** ранжирует лоты и фирмы по выраженности *признаков возможного сговора* на торгах, чтобы инспектор комитета начинал проверку с самых подозрительных случаев.
- **Выход:** риск 0–100 по лоту и по фирме, топ-3 причины (коды признаков с вкладом SHAP), список флагов с evidence, `model_version`.
- **Пользователи:** аналитики и инспекторы Комитета по конкуренции (роли `analyst`, `supervisor`).
- **Человек в контуре:** каждый результат — только повод для проверки. Модель не принимает решений и не формирует выводов о нарушении.

### Вне назначения (запрещённое использование)

- Автоматические санкции, отстранение от торгов, блокировки на основании одного скора.
- Публичные рейтинги «недобросовестных» фирм, передача скоров СМИ.
- Использование скора как доказательства в деле без самостоятельной проверки.
- Оценка физических лиц вне контекста торгов.

## 2. Данные

| Источник | Что берём | Период | Примечания |
|---|---|---|---|
| etender.uzex.uz | лоты, сделки, участники, победители, цены (если опубликованы) | согласовать (например, 2024–2026) | `specs/schema.md`, `docs/scraping-policy.md` |
| Реестр юрлиц | тип лица, дата регистрации, псевдонимы директоров/учредителей, хеши адреса/телефона | только флагнутые фирмы | `docs/data-protection.md` |
| Синтетика | сгенерированные рынки с внедрёнными схемами сговора | — | только для отладки и метрик «synthetic» |
| Реальные дела | решения комитета по делам о сговоре на торгах (если будут предоставлены) | — | только для метрик «real», хранятся отдельно |

Известные пробелы: цены проигравших заявок могут быть недоступны (`bids.bid_price` nullable) → признаки по ценам заявок работают только там, где они есть, иначе помечаются «не вычислено».

## 3. Признаки (screens)

Коды стабильны, используются в БД, API, справках и глоссарии. Пороги и веса **не публикуются** (раздел 8).

| Код | Признак | Идея | Уровень |
|---|---|---|---|
| `LOW_DISCOUNT` | малая скидка от стартовой цены | при сговоре цена договора близка к стартовой | лот |
| `SINGLE_BIDDER` / `FEW_BIDDERS` | один или мало участников | ограничение конкуренции | лот |
| `CO_BIDDING` | устойчивое соучастие | одни и те же фирмы часто участвуют вместе | пара фирм |
| `WINNER_ROTATION` | ротация победителей | группа фирм поочерёдно выигрывает у одного заказчика/в категории | группа |
| `PERPETUAL_RUNNER_UP` | «вечный второй» | фирма часто участвует, почти не выигрывает, проигрывает одним и тем же | фирма |
| `SHARED_FOUNDER` | общий учредитель | совпадение `person_id` учредителей у участников одного лота | пара фирм |
| `SHARED_DIRECTOR` | общий директор | совпадение `person_id` директоров | пара фирм |
| `SHARED_ADDRESS` / `SHARED_PHONE` | общий адрес / телефон | совпадение хешей нормализованных значений | пара фирм |
| `COVER_BID_PATTERN` | «прикрывающие» заявки | проигравшие цены равномерно выше победителя (только если цены есть) | лот |

Каждый флаг хранит `evidence` — воспроизводимые факты: какие лоты, какие значения, версия правила, `match_basis` (например, `name_hash_only` для совпадения только по ФИО — **слабый** признак из-за однофамильцев).

## 4. Модель

- **Правила:** каждый признак → флаг с `severity`; базовый скор — взвешенная сумма (веса из конфигурации).
- **Isolation Forest** (scikit-learn) по вектору числовых признаков лота/фирмы в пределах категории и региона — находит необычные комбинации, которые не ловят одиночные правила.
- **Итоговый скор 0–100:** калиброванная комбинация правил и аномальности; формула и веса фиксируются в `model_version`.
- **Объяснение:** SHAP-значения для части Isolation Forest + вклад правил → топ-3 причины. В интерфейсе причины показываются кодами признаков и человекочитаемым текстом, рядом — исходные цифры.
- **Воспроизводимость:** `model_version` = версия кода + хеш конфигурации + хеш обучающего среза; фиксированный `random_state`.

## 5. Метрики

**Метрики на синтетике и на реальных делах никогда не смешиваются** и показываются в разных таблицах с подписью источника.

| Набор | Метрики | Значение |
|---|---|---|
| synthetic | precision@k (k = 20, 50), recall внедрённых схем, доля ложных флагов на «чистых» рынках | заполняется 05-model |
| real (дела комитета) | precision@k, recall известных дел, медианный ранг известного дела | заполняется, если комитет предоставит данные |
| стабильность | доля лотов, сменивших категорию риска при перезапуске / при сдвиге периода | заполняется 05-model |
| покрытие | доля лотов, для которых вычислены все признаки (цены, реестр) | заполняется 05-model |

## 6. Ограничения

- Малые и узкие рынки (регион × категория) естественно имеют мало участников и стабильных победителей → завышенный риск без сговора.
- Монополии по закону, единственный поставщик, специфические требования заказчика.
- Однофамильцы: совпадение `person_id` ≠ один человек.
- Общие адреса бизнес-центров, общих бухгалтерских фирм → `SHARED_ADDRESS`/`SHARED_PHONE` без связи.
- Отсутствие цен заявок ограничивает ценовые признаки.
- Isolation Forest помечает «необычное», а не «незаконное».
- Данные площадки могут содержать ошибки и задержки публикации.

## 7. Риски ложных срабатываний и меры

| Риск | Мера |
|---|---|
| Флаг на честной фирме из-за малого рынка | нормировка признаков по рынку (регион × категория), минимальный объём рынка для части признаков |
| Однофамильцы | `match_basis` в evidence, пониженный вес совпадения только по имени, подтверждение вторым признаком |
| Общий адрес бизнес-центра | список «массовых» адресов (по частоте хеша) с пониженным весом |
| Инспектор воспринимает скор как вывод | формулировки «признаки», дисклеймер, исходные цифры рядом со справкой |
| Публикация ложного флага | экспорт только `supervisor` с аудитом, `DEMO_MODE` для демо и презентаций |

## 8. Пороги, веса и подстройка картеля

- Пороги и веса **продакшн-режима** задаются в конфигурации вне репозитория (`RISK_CONFIG_PATH`), а не в коде.
- В репозитории — только демо-конфигурация с явной пометкой «DEMO — не для продакшна».
- В презентации и документации — описание признаков без числовых порогов.
- Конфигурация версионируется отдельно (у комитета), её хеш входит в `model_version`.

## 9. Мониторинг и обновление

- Пересчёт при поступлении новых данных; перекалибровка — по решению команды/комитета с новой `model_version`.
- Старые `risk_scores` не перезаписываются — хранятся с версией для воспроизводимости.
- Отзывы инспекторов («подтверждено / ложный флаг») — источник для оценки на реальных данных (Фаза пилота).

## 10. Справедливость и этика

- Проверять распределение скоров по регионам, размерам фирм, типам лиц (юрлицо/ИП): систематический перекос → разбор признаков.
- Не использовать признаки, не связанные с поведением на торгах (национальность, пол, возраст — не собираются вовсе).

## 11. Известные ошибки

Пока нет (заполняется по итогам проверок и инцидентов, `docs/incident-response.md`, раздел 6).
