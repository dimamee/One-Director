# Политика сбора данных

Версия 0.1 (Фаза 0). Компоненты: `src/one_director/data/` (01-data), `src/one_director/registry/` (02-registry), `src/one_director/security/http_client.py` (Фаза 1).

## 1. Принципы

1. Собираем **только открыто опубликованные** данные о закупках — то, что любой посетитель видит без входа в систему.
2. Мы **гость** на площадке: нагрузка минимальная, поведение предсказуемое, мы честно представляемся.
3. Ограничение или блокировка — **сигнал остановиться и связаться с владельцем**, а не обходить.
4. Собираем **минимум полей** (`specs/schema.md`), без документов и договоров.

## 2. До первого запуска (делают люди, не агенты)

- [ ] Прочитать `robots.txt` и пользовательское соглашение etender.uzex.uz; зафиксировать выводы в PR (дата, ссылка, цитата ключевых пунктов).
- [ ] Выяснить, есть ли официальный канал открытых данных (open data портал, выгрузка, API для исследователей) — предпочитаем его.
- [ ] По возможности получить письменное согласие УзРТСБ / оператора площадки или подтверждение от организаторов хакатона.
- [ ] Согласовать источник реестра юрлиц (официальный, с открытым доступом) и его условия.
- [ ] Заполнить контакт команды для User-Agent.
- [ ] Агенты **не обращаются** к площадке без явного разрешения человека на конкретный запуск; разработка и тесты — только на фикстурах.

## 3. Технические правила (`security/http_client.py`)

| Правило | Значение |
|---|---|
| Эндпоинты | только публичные, без авторизации, cookies с учётными данными не используются |
| Частота | не чаще **1 запроса в секунду**, одно соединение, без параллельных воркеров |
| Окно | крупные выгрузки — в часы низкой нагрузки (ночью по Ташкенту) |
| Повторы | только при сетевых ошибках и 5xx: экспоненциальная задержка с джиттером (1, 2, 4, 8, 16 с …, максимум 5 мин), не более 5 попыток |
| `Retry-After` | соблюдается всегда |
| **429 / 403 / 401** | **немедленная остановка всего запуска**, без повторов; уведомление человеку; возобновление только после разбора |
| TLS | проверка сертификата всегда включена (`verify=False` запрещён хуком pre-commit) |
| Таймауты | connect 5 с, read 30 с, общий 60 с на запрос |
| Размер ответа | не более 10 МБ (потоковое чтение с обрывом), только `application/json` |
| Хосты | allowlist: `apietender.uzex.uz` (публичный JSON API, которым пользуется сайт etender.uzex.uz) и согласованный источник реестра; редиректы на другие хосты отклоняются. Файловый хост `etender-fileservice.uzex.uz` **не входит** в allowlist (D-29, D-04) |
| User-Agent | `OneDirector-research/<версия> (+<контакт команды>; hackathon AI-10)` |
| Запрещено | обход CAPTCHA, ротация прокси/IP, подделка браузерных заголовков, вход под чужими учётками, сбор закрытых разделов |
| Kill switch | переменная `SCRAPER_ENABLED=false` останавливает сбор без изменения кода |

## 4. Объём

**Публичные эндпоинты, которые разрешено вызывать** (проверено 25–26.11.2026, D-29): `POST /api/common/DealsList`, `GET /api/common/GetProposalUsers/{trade_id}`, `GET /api/common/GetTrade/{trade_id}/0`, `POST /api/common/NotDealedList`. Остальные — только после PR в этот файл.

- Только лоты и сделки за согласованный период и категории, нужные для демо и пилота.
- **Никакой массовой загрузки документов, договоров, вложений, сканов.** Ссылка `source_url` хранится, сам документ — нет.
- *Предложение D-04 (ждёт подтверждения оргкомитета/команды, до него — запрещено):* для сценария A разрешить **точечную** загрузку PDF «дополнительного протокола» только для лотов демо и бенчмарка (не более 300 файлов за весь проект), по явному разрешению человека на запуск, с извлечением только цен участников и немедленным удалением файла после разбора. До подтверждения цены заявок берутся только из официального датасета комитета/RTAM.
- Инкрементальный сбор: уже полученные завершённые лоты повторно не запрашиваются (кэш по `trade_id`).
- **Реестр юрлиц — только точечно**, для фирм, которые участвовали во флагнутых лотах; без обхода реестра целиком.

## 5. Валидация ответов

- Каждый ответ разбирается pydantic-моделью (`src/one_director/data/`): типы, диапазоны (цены ≥ 0, даты в разумном окне, ИНН — 9 цифр).
- **Неожиданные поля** логируются (имя поля, без значения) и не ломают пайплайн; **отсутствующие обязательные** — запись откладывается в карантин с причиной.
- Текстовые поля (названия, описания) хранятся как есть, но помечены как **недоверенный ввод** — они экранируются при выводе и не передаются в LLM как инструкции (`docs/llm-safety.md`).
- Аномалии (цена договора больше стартовой в разы, отрицательное число участников) → карантин, не в расчёт признаков.

## 6. Хранение сырых данных

- Сырые ответы → `data/raw/` (в `.gitignore`, `.dockerignore`, запрещены к чтению агентам) → после успешной обработки **удаляются**, не позже чем через 7 дней.
- В `data/processed/` попадают только поля из `specs/schema.md`.

## 7. Тесты

- Тесты сборщика используют только фикстуры (`tests/fixtures/`) и mock-транспорт httpx; реальная сеть в тестах запрещена.
- Обязательные тесты: лимит 1 rps, остановка на 429/403, обрыв по размеру, отказ на чужой хост, обработка неожиданных полей.

## 8. Если площадка ограничила доступ

1. Сборщик сам останавливается (429/403).
2. Ответственный в команде фиксирует время, ответ, последние запросы (без ПДн).
3. Связаться с оператором площадки / организаторами, объяснить цель, предложить согласованный режим.
4. До ответа — работаем на уже собранных данных и синтетике. Обход ограничения запрещён.
