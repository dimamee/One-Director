# Задача: граф связей фирм, людей (псевдонимы) и адресов

**Роль:** разработчик графовой аналитики (networkx).

**Вход:** `bids`, `firms`, `persons`, `flags`, `risk_scores` (`specs/schema.md`).

**Выход:**
- `src/one_director/graph/` — построение графа (узлы: фирма, человек-псевдоним, адрес-хеш, лот; рёбра: `bid`, `won`, `director`, `founder`, `same_address`, `same_phone`, `co_bid`), метрики (компоненты, центральность, плотные группы) для 03-screens/05-model.
- Функция подграфа для API `GET /graph` (`specs/api-contract.md`): центр, глубина 1–2, лимит узлов, флаг `truncated`.

**Готово, когда:**
- [ ] Подграф соответствует контракту `GET /graph` (тест на схему ответа).
- [ ] Лимиты `depth ≤ 2`, `max_nodes ≤ 300` соблюдаются и на «звёздных» узлах (тест на узел с 10 000 соседей).
- [ ] Метки — простой текст, уже замаскированный по правилам (`security.masking`); узлы людей — `P-xxxx`, адресов — `A-xxxx`.
- [ ] Детерминированный порядок узлов/рёбер.
- [ ] ruff, mypy, bandit, pytest зелёные.

**Тесты:** `tests/graph/` — построение на синтетике, лимиты, маскирование меток, отсутствие ФИО и полных хешей.

**Можно менять:** `src/one_director/graph/`, `tests/graph/`.

**Нельзя менять:** формат ответа `/graph` без PR в `specs/api-contract.md`; другие модули.

**Требования безопасности:**
- Узлы людей — только псевдонимы; полный `person_id` и хеши наружу не отдаются (короткий префикс).
- Метки не содержат HTML; экранирование выполняет фронт, но граф не должен порождать разметку.
- Ограничение размера подграфа (защита от DoS и от деанонимизации по «уникальному» окружению).
