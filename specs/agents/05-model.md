# Задача: риск-скор 0–100 (правила + Isolation Forest) с объяснением SHAP

**Роль:** ML-инженер.

**Вход:** `flags` (03-screens), метрики графа (04-graph), таблицы `lots`/`bids`/`firms`; конфигурация весов (демо в модуле, продакшн — `RISK_CONFIG_PATH`); `docs/model-card.md`.

**Выход:**
- `src/one_director/model/` — вектор признаков, Isolation Forest (scikit-learn), комбинирование с правилами, калибровка в 0–100, SHAP-объяснения, топ-3 причины.
- Таблица `risk_scores` с `model_version`.
- Заполненные разделы 4–7 и 11 `docs/model-card.md` (метрики synthetic и real — в разных таблицах).

**Готово, когда:**
- [ ] Каждый скор имеет `model_version` (версия кода + хеш конфигурации + хеш обучающего среза) и ровно 3 причины.
- [ ] Детерминизм: фиксированный `random_state`, повторный запуск → те же скоры.
- [ ] На синтетике precision@20 и recall внедрённых схем посчитаны и записаны в model card; метрики на реальных делах (если есть) — отдельно.
- [ ] Веса и пороги продакшна не захардкожены.
- [ ] ruff, mypy, bandit, pytest зелёные.

**Тесты:** `tests/model/` — диапазон 0–100, 3 причины, детерминизм, монотонность (добавление сильного флага не снижает скор), разделение synthetic/real.

**Можно менять:** `src/one_director/model/`, `tests/model/`, `docs/model-card.md` (разделы 4–7, 11).

**Нельзя менять:** назначение и ограничения использования в model card (разделы 1, 8, 10), другие модули.

**Требования безопасности:**
- Пороги и веса продакшна — только из конфигурации вне репозитория.
- Обучающие срезы и модели (`*.joblib`) не коммитятся (только `data/processed/`); не загружать pickle/joblib из недоверенных источников.
- Скор и причины — «индикатор риска», без слов «нарушение»/«картель».
- Метрики synthetic и real **никогда не смешиваются**.
