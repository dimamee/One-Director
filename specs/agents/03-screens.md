# Задача: признаки сговора (screens) с воспроизводимым evidence

**Роль:** аналитик-разработчик признаков. Вычисляет флаги по лотам, фирмам и парам фирм.

**Вход:** таблицы `lots`, `bids`, `firms`, `persons` (`specs/schema.md`); каталог признаков `docs/model-card.md` (раздел 3); конфигурация порогов (демо-файл в модуле + путь `RISK_CONFIG_PATH` для продакшна; формат — *предложение* D-47).

**Проходы (D-14, D-48):**
- **Проход 1 — структурные признаки** по `lots` и `bids`: `LOW_DISCOUNT`, `SINGLE_BIDDER`, `FEW_BIDDERS`, `CO_BIDDING`, `WINNER_ROTATION`, `PERPETUAL_RUNNER_UP`, `COVER_BID_PATTERN` (только если есть цены заявок и `price_screens_enabled`, D-6).
- **Проход 2 — связи через реестр** по `firms` и `persons`: `SHARED_FOUNDER`, `SHARED_DIRECTOR`, `SHARED_ADDRESS`, `SHARED_PHONE`.

**Выход:**
- `src/one_director/screens/` — по функции на признак (список — в «Проходах» выше).
- `src/one_director/screens/synthetic.py` — генератор синтетических рынков с внедрёнными схемами; его же импортируют тесты 05-model (D-27, подтвердить).
- Таблица `flags` с `evidence`, `rule_version`, `severity`; признак уровня «группа» — по D-44.
- Таблица `screen_coverage` — «не вычислено» с причиной (*предложение* D-45).
- Пока нет `data.schema.Flag`, допустима временная копия колонок `flags` в модуле с пометкой «временно, D-43»; удаляется сразу после выхода модели.

**Готово, когда:**
- [ ] Каждый признак покрыт тестом на синтетике: срабатывает на внедрённой схеме и не срабатывает на «чистом» рынке.
- [ ] `evidence` воспроизводим: по нему одному можно пересчитать флаг (тест пересчёта).
- [ ] Пороги и веса читаются из конфигурации; в коде нет числовых порогов продакшна (ревьюер проверяет).
- [ ] Признаки, которые нельзя вычислить (нет цен заявок), помечаются «не вычислено», а не считаются нулём.
- [ ] Лоты с расхождением числа участников (R2, `specs/schema.md` → `bids`) не входят в признаки по списку заявок — «не вычислено» с причиной `participants_mismatch`.
- [ ] Признаки нормируются по рынку (регион × категория).
- [ ] Деньги в `evidence` — строка с 2 знаками после точки (D-42): `evidence` одинаков на строках из DuckDB, на моделях `data.schema` и на синтетике.
- [ ] *Проход 2:* совпадения только по ФИО помечены `match_basis: name_hash_only`.
- [ ] ruff, mypy, bandit, pytest зелёные.

**Тесты:** `tests/screens/` — синтетические рынки (генератор `src/one_director/screens/synthetic.py`, D-27), граничные случаи (один лот, нет цен; в проходе 2 — `unknown` тип лица), детерминизм.

**Можно менять:** `src/one_director/screens/`, `tests/screens/`.

**Нельзя менять:** схему `flags` без PR в `specs/schema.md`; коды признаков без PR в `docs/model-card.md` и `docs/glossary-uz-ru.md`; другие модули.

**Требования безопасности:**
- Пороги продакшна — **не в публичном коде** (защита от подстройки картеля).
- `evidence` содержит ID лотов, значения и версии — **без ФИО**, без полных хешей адресов (достаточно ссылки на совпадение).
- В `evidence` ИНН — только под ключами `*_inn` / `*_inns` (по ним 07 маскирует); применённые пороги — только под ключом `params`, который не уходит в API, PDF и LLM (*предложение* D-46).
- SQL к DuckDB — только параметризованный.
- Названия флагов и тексты — «признак», не «нарушение».
