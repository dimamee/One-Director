# Задача: точечное обогащение фирм из флагнутых лотов данными реестра

**Роль:** инженер данных по реестру юрлиц. Заполняет `firms` и `persons` только для фирм, участвовавших во флагнутых лотах, сразу псевдонимизируя людей.

**Вход:**
- Список ИНН участников лотов, у которых есть хотя бы один флаг (`flags` от 03-screens).
- Согласованный людьми источник реестра (открытый вопрос; без него задача не начинается) и его обезличенные фикстуры в `tests/fixtures/registry/`.
- `security.pseudonymize`, `security.http_client` (Фаза 1).

**Выход:**
- `src/one_director/registry/` — клиент источника, разбор ответа, запись `firms` и `persons` (`specs/schema.md`).

**Готово, когда:**
- [ ] Запрашиваются только ИНН из флагнутых лотов (тест: на вход подан «лишний» ИНН — запроса нет).
- [ ] ФИО директоров/учредителей превращаются в `person_id` **в памяти** и нигде не записываются в открытом виде (тест сканирует все выходные файлы и логи на канареечные ФИО).
- [ ] Адреса и телефоны хранятся только как `address_hash`/`phone_hash`.
- [ ] `entity_type` заполнен; при сомнении — `unknown`.
- [ ] Повторный запрос той же фирмы не чаще раза в N дней (кэш по `registry_checked_at`).
- [ ] ruff, mypy, bandit, pytest зелёные.

**Тесты:** `tests/registry/` — разбор фикстур, псевдонимизация (одинаковое ФИО на латинице и кириллице → один `person_id`), отсутствие ФИО в выходе, фильтр «только флагнутые», mock-транспорт.

**Можно менять:** `src/one_director/registry/`, `tests/registry/`, `tests/fixtures/registry/` (только синтетика/обезличенное).

**Нельзя менять:** `security/` (в т. ч. алгоритм нормализации — только через PR людям), схему таблиц без PR в `specs/schema.md`, другие модули.

**Требования безопасности:**
- **Только фирмы из флагнутых лотов**, никакого обхода реестра целиком.
- **Псевдонимизация людей** через `security.pseudonymize`; не собирать паспортные данные, ПИНФЛ, личные телефоны, домашние адреса, даты рождения.
- Те же правила сети, что у 01-data (≤ 1 rps, стоп на 429/403, TLS, таймауты, User-Agent, без логина).
- `PSEUDONYM_SALT` только через `security.settings`; никогда не логировать.
- Совпадение только по ФИО помечать как слабое (`match_basis: name_hash_only`).
